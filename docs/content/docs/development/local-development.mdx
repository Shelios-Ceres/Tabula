# Local Development

The desktop client is written in C# with .NET 10 and WinUI 3 (Windows App SDK), draws the canvas with Win2D, and lives in `desktop/`.

## Build, run and test

```bash
dotnet build desktop/InfiniteCanvas.sln
```

```bash
dotnet test desktop/tests/InfiniteCanvas.Tests
```

The built app is at `desktop/src/InfiniteCanvas.App/bin/x64/Debug/net10.0-windows10.0.22621.0/win-x64/InfiniteCanvas.exe`.

## Testing with a separate data folder

The client reads and writes `%LocalAppData%\InfiniteCanvas` by default. For testing, point the `INFINITE_CANVAS_DATA` environment variable at another folder so the test instance uses its own canvases and settings, and build with `-p:BaseOutputPath=...` into a temporary folder so it does not clash with a running client.

## Code layout

| Folder | Contents |
| --- | --- |
| `desktop/src/InfiniteCanvas.Core` | Canvas model, connection rules, undo history, project and settings storage, model family capabilities |
| `desktop/src/InfiniteCanvas.Providers` | Native adapters for the five vendors |
| `desktop/src/InfiniteCanvas.Agents` | Local agent integration: ACP client, canvas MCP tools and the named-pipe server |
| `desktop/src/InfiniteCanvas.App` | WinUI 3 UI: `Pages` (canvas list, canvas, settings) and `Board` (canvas engine, nodes, generation panel, scheduling) |
| `desktop/tests/InfiniteCanvas.Tests` | Core rules and request / response parsing tests |

## Documentation site

To work on the documentation site, run in `docs`:

```bash
bun install
bun run dev
```

Common locations:

- Canvas, nodes and the generation panel: `desktop/src/InfiniteCanvas.App/Board/`
- Vendor requests: `desktop/src/InfiniteCanvas.Providers/`, with cases in `desktop/tests/InfiniteCanvas.Tests/ProviderTests.cs`
- Model capabilities: `desktop/src/InfiniteCanvas.Core/Models/ModelFamilies.cs`
- Agents and MCP tools: `desktop/src/InfiniteCanvas.Agents/`
- Documentation content: `docs/content/docs/`
