# 待测试

- 图片对比视图（2.3；编译无警告，单元测试通过）：选中两张位图（左边的是 A）后按 `C`，或点选区工具条上新增的「对比」按钮；单独的 `C` 键原本没有占用（只有 `Ctrl+C`），所以没有加右键菜单项。它在和双击预览同一个全屏层里打开，有四种模式：滑块（拖动分割线）、叠加（B 的透明度）、差异（增益 1×–8×，灰度或热力图）和闪烁（A、B 交替）。B 会等比缩放到 A 的宽度并居中，角落会注明；方向键（Shift 一次 10 像素）或在其他模式下拖动可以平移 B 来对齐（只做偏移，角落显示偏移量，有重置按钮）。Esc 或关闭按钮退出。SVG 不参与对比。Agent 有只读工具 `image_compare {a, b, threshold}`：返回平均差和最大差（0–1）、变化超过阈值（默认 0.05）的像素占比、变化区域的包围盒（占 A 宽高的比例）、比较的像素数，尺寸不同时附说明；它在长边 1024 像素的缩略图上测量（和 `canvas_get_image` 看到的一样大）。手测：把一张图和它轻微修改过的副本在每种模式下对比，差异模式应该只在修改处亮起；对比两张不同尺寸的图，看到「B 已缩放」提示；对同一对图运行 `image_compare`。
- 拼版 / 联系表（2.2；编译无警告，单元测试通过）：选中两张以上位图（不含 SVG；折叠的批次只取摞头）后右键选「拼版…」，或点选区工具条上的「拼版…」。对话框里可调布局（一行 / 一列 / 网格）、列数（网格用，0 = 自动）、适配（等高或等宽，取最小的一张，谁都不放大）、间距、外边距和背景（白 / 浅灰 / 黑 / 透明），实时预览；点预览里的图片选中它，用左右箭头按钮调整顺序。「按头顶和脚底对齐」（只在一行且等高时可用）给每张图加两条可拖的线（实线是头顶，虚线是脚底）：所有人物缩到最小那个人物的高度，脚底落在同一条线上。「拼到新节点」把结果放在输入右侧的新图片节点里并从每张连线，一次撤销；除显卡的位图上限外没有尺寸限制，超过时整体等比缩小并在对话框里写「已缩小到 x%」。输入全是 JPEG 且背景不透明时出 JPEG，否则出 PNG。设置记在结果节点上：右键它选「按上次设置重新拼」会带着这些设置重新打开对话框，就地换图（同一个节点和连线，一次撤销，旧文件保留）；输入被删掉了会点名提示、不拼。Agent 用新工具 `canvas_compose {ids, layout, columns, gap, margin, background, fit, marks}`，所有检查都在绘制之前完成。已知问题：带内嵌颜色配置的 PNG 拼完颜色可能略有变化（渲染按 sRGB 处理）。手测：四张 2160×3840 竖图拼一行得到 8960×3968，文件尺寸与对话框底部一致；透明背景出 PNG；人物大小不一时开对齐线，出图里人物等高、脚底同线，重新拼时线还在；选区里混有 SVG 和文本节点时被忽略，只剩一张位图时菜单里没有这一项。
- 留一删余 / 设为定稿（2.1；编译无警告，单元测试通过）：右键一批（摞，收起或展开都行）里的一张，选「留这张，删掉这一摞的其他」：经过常规确认（没有「不再提示」）后，同批其余的从画布上移除，留下的这张离开摞，占摞头的位置和分组（这一批起过名就沿用名字），并接上被移除各张的连线；不删任何文件，一次撤销全部还原。右键图片选「设为定稿…」：选要被取代的图片（先列出和它一起选中的，再列出名字含「定稿」或「官方」的分组里的图片，都没有就列全部）；新图占它的位置、宽度、标题、分组和连线，旧节点从画布上消失（文件保留）。资料库里有和旧图同名的文件时，会出现一个默认勾选的复选框，写明旧文件移到回收站、由新图以同名替换；这一步不能在画布里撤销。Agent 在 `canvas_apply_ops` 里有 `keep_one {id}` 和 `promote {id, replaces, library}` 两个 op（`library` 默认 false，Agent 必须明确要求才会动回收站），各自一步撤销；资料库替换失败时 `promote` 在改动任何东西之前就停止；一批里有多张的图不能被取代（先用 keep_one）。手测：展开一批，留下第三张（摞头有连线和分组）；在「定稿」分组里让一张图取代另一张，资料库复选框勾上和不勾各试一次，每次撤销一次。
- 第一阶段审查后续（2.0；编译无警告，单元测试通过）：(a) 资料库里不带扩展名的名字对应不止一个文件（如 猫.png 和 猫.jpg）时，`library_rename`、`library_remove`（在 `failed` 里报告）和 `library_place` 现在返回错误并列出完整文件名，不再对最新的那个动手；写完整文件名仍然可用。(b) 通过 MCP 的 `stack_close` 会把此时被盖住的卡片移出选区、保留摞头，和用展开按钮收起一致。(c) `canvas_generate` 用 `layout=row` 或 `grid` 生成多张时，会找一个整排 / 整个网格都空着的起点，而不是只看一张卡（生成器对紧挨着已有图片的来源节点放置输出时也一样）。(d) `canvas_generate` 的 `dryRun` 在提示词为空时，只要真实调用会被拒绝就报告 `cannotStart`，包括输入只有空的图片或文本节点的情况。手测：在视图中心右侧稍远处放一个节点，用 `layout=row` 生成四张，这一排必须从那个节点之后开始。
- 第一阶段 Agent 工具的审查修复（编译无警告，单元测试通过；重试修复没有用真实服务商实测）：重试一批结果里失败的那一张时，原先会抹掉它的 `stack`、`stackOpen` 和 `sourceId`，卡片因此脱离这一摞，再次失败后也无法再经来源节点重试；现在重试的节点保留这三项（`NodeKeys.OutputOptions`）。`canvas_replace_media` 在文件复制不了（被占用、没有权限）时返回具体原因而不是一句笼统的失败，路径末尾带空格或点时按规范化后的路径使用。经 `options` 直接写入的 `gap` 只有是不小于 0 的有限数时才生效（`Stacks.GapOf`），间距大到算出的位置溢出时改用默认的 24，一批结果不会再得到无法保存的坐标（`gap` 仍然没有上限）。单元测试不再往本机回收站里丢文件（测试里替换了 `LibraryStore.Recycle`；唯一真正调用系统回收的步骤只在设置 `INFINITE_CANVAS_TEST_RECYCLE_BIN=1` 时运行）。手测：从生成配置节点（或已有图片的图片节点）生成一批四张并让其中一张失败（例如中途停止），对那张连续重试两次：它应一直留在这一摞里（折叠时上面不多出一张卡，展开后 `stack_close` 仍能把它收回），第二次重试也能开始；用另一个程序占用一个文件再调用 `canvas_replace_media`：报错里应写明原因。
- Agent 资料库回收不再弹窗（1.3 的后续；编译无警告，单元测试通过）：`library_add replace` 和 `library_remove` 现在经 `ProjectStore.RecycleSilently`（`SHFileOperation`，关闭进度、确认和错误界面，保留撤销）把文件移到回收站，不再走可能弹出错误对话框的 shell 调用；失败会作为工具错误返回，资料库文件原样保留，`replace` 时回收失败会保留旧文件且不留下临时文件。只有本地固定盘上的文件才会处理（可移动盘和网络盘没有回收站，直接失败而不是被永久删除）；文件太大放不进回收站、或该盘关闭了回收站时，系统会在永久删除前询问，所以这种少见情况仍可能出现提示。资料库面板自己的删除行为不变。手测：用 `--mcp-bridge` 删除和替换资料库文件，到回收站里能找到旧文件；在其他程序里占用一个资料库文件再试这两个操作：调用应立刻返回错误且没有任何窗口。
- Agent 费用估算（1.5；编译无警告，单元测试通过，尚未用真实 MCP 客户端实测）：`canvas_generate` 和 `canvas_run_generation` 对图片生成返回 `estimatedCost {amount, currency, basis}`，和生成面板「预计花费」用同一个 `Prices.EstimateImage` 与同一份输入列表；没有官方单价、也没有同模型同设置的上次用量时，返回明确的 `null` 加 `estimatedCostNote`，文本和语音说明暂不估价。`canvas_generate` 新增 `dryRun`：校验和真实调用完全一样并返回估价（缺模型或 Key 时附 `cannotStart`），但不建节点、不记撤销历史、不发请求。新增只读 `usage_summary {since}`（yyyy-MM-dd、`today`、`month`，默认今天），按币种列出本机账本：火山方舟、千问是人民币，其余是美元，互不相加；金额只含有 token 单价的模型（Gemini、GPT Image），其余写在 `unpricedModels` 里，按张计价的渠道只给数量、金额为 null。不会因为费用拒绝或限制生成。手测：让 Agent 对一个有单价的模型做 dryRun，和生成面板里同样设置的预计花费对比；在两个服务商各生成几张后运行 `usage_summary`，和额度页对比。
- Agent 批量排版（1.4；编译无警告，单元测试通过，已在独立测试实例上通过它自己的 --mcp-bridge 实测：展开按钮和 `stack_open` / `stack_close` 得到同样的网格，各撤销一次即可还原；真实生成时的 `layout` 没有跑，因为需要服务商）：`canvas_generate` 新增 `layout`（`stack` 默认、`row`、`grid`）和 `gap`，`canvas_apply_ops` 的 `add_node` 也一样，记在节点上，下一批生成时才生效：选 `row` 或 `grid` 时结果从第一张的左上角直接排开，不再叠成一摞（gap 默认 24，必须是不小于 0 的有限数）。新增 `stack_open {id, layout?, gap?}` 和 `stack_close {id}`，给任意一个成员的 ID 就能把已有的一批展开（row 或 grid，默认 grid）或收起；整个操作一步撤销。批次卡上的展开按钮现在走同一个 Core 函数，请确认点击展开 / 收起的效果不变（同样的网格、仍有滑动动画）。重试单张失败的结果不会重新排版，被你拖到别处的成员保持原位。手测：用 `layout=row` 和 `grid`、`gap=60` 各生成四张图；用 `stack_open` / `stack_close` 展开、收起一批旧结果；每次操作后撤销一次。
- Agent 资料库管理（1.3；编译无警告，单元测试通过，已在独立测试实例上通过它自己的 --mcp-bridge 实测：改名后资料库面板立即刷新，被占用文件让覆盖和删除立刻失败且没有任何窗口）：`library_add` 新增 `replace`（默认 false）：MCP 路径下资料库里已有同名文件时报错并提示用 `replace`（在资料库面板里拖入仍然加数字后缀）；`replace=true` 先复制新文件，再把旧文件移到回收站并沿用原文件名。新增 `library_rename {name, newName}` 只改文件名、扩展名不变（重名、空名、以点结尾、含 `\ / : * ? " < > |`、CON / NUL / COM1 等 Windows 设备名、改扩展名都会被拒绝）；新增 `library_remove {names}` 把文件移到回收站，返回 `removed` 和 `failed: [{name, reason}]`。名字只在当前画布自己的资料库文件夹里查找，任何路径都出不了这个文件夹；被其他程序占用的文件会报告失败而不是去回收，避免弹出系统对话框卡住调用。三个工具都标为破坏性，并说明不能撤销（资料库不在画布撤销记录里）。从资料库放上画布的节点用的是复制到画布文件夹里的副本，所以改名或删除资料库文件不会让节点断图。手测：同一个节点加入两次，再用 `replace`；用 `--mcp-bridge` 改名和删除，看资料库面板自动刷新；从回收站找回被删文件。
- Agent 导入文件与替换媒体（1.2；编译无警告，单元测试通过，已在独立测试实例上通过它自己的 --mcp-bridge 实测：`canvas_replace_media` 及其撤销，带被占用文件的导入返回 failed 且没有任何窗口）：新增 `canvas_import_file {paths, x?, y?}`，把本机文件复制进画布文件夹，成为新的图片 / 视频 / 音频节点，返回 `nodeIds` 和 `failed: [{path, reason}]`；新增 `canvas_replace_media {nodeId, path}`，给已有媒体节点换上一个新编号的文件，节点 ID、位置、宽度、分组、摞和连线都不变（整次一步撤销，旧文件仍在画布文件夹里；节点上的蒙版、标注、点选框选和会话关联描述的是旧图，会一并清除）。路径必须是带盘符的绝对路径、文件存在、扩展名属于支持的媒体类型，并且不是 UNC / 设备（\ 和 / 任意混用都算）/ 备用数据流 / 保留设备名路径，也不是网络驱动器上的文件或指向它的链接；不设文件大小上限，与界面拖入一致。节点正在生成或文件类型不一致时拒绝替换。MCP 导入不再弹窗：`library_place` 遇到读不了的文件现在返回错误（或在 `failed` 里列出，同时放好能放的文件），不会再卡在模态对话框上；界面里拖入或选择文件失败时仍然弹出原来的提示。手测：按路径导入一张 PNG 和一个 MP4，把一个图片节点替换成另一张图并撤销一次，再用另一个程序占用一个文件，在客户端窗口可见时用 `library_place` / `canvas_import_file` 导入它，不应出现任何对话框。
- Agent 精简读取与分组编辑（1.1；编译无警告，单元测试通过，已在独立测试实例上通过它自己的 --mcp-bridge 实测：40 个节点的画布默认 5,897 字符，`detail=full` 为 24,612 字符，4 张一批的状态 442 字符；`group_add` 后分组 ID、标题、连线都在，一次撤销整张画布回到操作前）：`canvas_get_state` 默认只返回节点精简字段（不含提示词、正文、生成参数和 options），支持 `detail`、`ids`、`groupId`、`rect` 筛选，连线只保留两端都在结果里的；新增只读 `canvas_get_node {ids}` 返回完整字段；`generation_get_status` 的 `batch` 成员只有 id、status、file、error。`canvas_apply_ops` 新增 `group_add {id, ids, fit}` 和 `group_remove {ids, fit}`，把节点加入或移出已有分组（折叠的摞整摞移动）：分组 ID、标题和连线不变，移空的分组被删除，整批只算一步撤销。请在 40 个节点的画布上确认默认状态明显变小，并用 `--mcp-bridge` 实测 group_add / group_remove 与一次撤销。`group` 的报错现在区分「不足两个节点（列出找不到的 ID）」和「已经都在同一个分组」。
